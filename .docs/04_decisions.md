## DEC-006：GUI 使用业务语义层级，不直接暴露后端六分区

### 状态

```text
Accepted
```

### 决策

用户可见的场景任务一级层级采用：

```text
① 任务设置
② 目标参数
③ 场景与运动
④ 环境与观测
⑤ 计算与输出
```

不直接使用：

```text
CASE
ENVIRONMENT
GROUP_STATE
OBSERVATION
TARGET_PHYSICS
TARGET_SCENE
```

作为 GUI 一级导航。

### 背景

后端六分区是程序数据合同，适合机器解析和模块调用，
但直接用于 GUI 会增加用户理解成本。

旧总体设计图中的部分输入也已与当前源码不一致，
例如地球红外、对流边界等在当前正向程序中不存在。

### 理由

- 降低用户理解成本；
- 保持界面与业务流程一致；
- 避免 GUI 看起来像 JSON 编辑器；
- 允许后端字段结构变化时尽量不影响用户界面；
- 便于将复杂参数分成普通设置和高级设置。

### 影响范围

影响：

- 左侧任务树；
- 中部参数编辑器；
- GUI 数据模型；
- JSON 映射层；
- 后续 Codex Prompt。

不影响：

- `forward-request-v1` 数据合同；
- 01/02/04 后端接口；
- 03 run-based 输入。

### 后续动作

- 新增 GUI 业务任务数据模型；
- 新增业务字段到后端合同的映射层；
- 逐项核对当前源码真实支持参数。

## DEC-007：GUI 参数以当前源码能力为准，旧流程图仅作流程参考

### 状态

```text
Accepted
```

### 决策

GUI 中出现的参数必须能够在当前正式源码和数据合同中找到依据。

旧总体设计图仅用于：

```text
理解用户任务流程
理解模块之间的业务关系
辅助设计信息层级
```

不得用于：

```text
直接补充当前源码未支持的参数
```

### 当前明确不加入

```text
地球红外边界
对流换热边界
环境流体温度
```

### 后续动作

每增加一个 GUI 参数，都执行“源码支持检查”。
