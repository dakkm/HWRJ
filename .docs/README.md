# GUI 维护文档使用说明

本目录用于维护 `Pre-process` MFC GUI 重构项目。

建议放置：

```text
Pre-process\
├─ .docs\
│  ├─ README.md
│  ├─ 00_project_brief.md
│  ├─ 01_architecture.md
│  ├─ 02_workflow.md
│  ├─ 03_experiments.md
│  ├─ 04_decisions.md
│  ├─ 05_known_issues.md
│  └─ 06_prompt_log.md
├─ Pre-process.sln
├─ Pre-process\
├─ coreprogram\
└─ x64\
```

当前最重要的规则：

```text
1. coreprogram 是冻结后端；
2. forward-request-v1 是内部合同，不是 GUI 页面结构；
3. GUI 使用业务语义层级；
4. 所有 GUI 参数必须以当前源码实际支持为准；
5. 旧总体设计图只作流程参考，不作为参数真值源。
```

当前 GUI 一级层级：

```text
① 任务设置
② 目标参数（含场景搜索相似度验收阈值）
③ 场景与运动
④ 环境与观测
```

运行时请求由各功能模块根据当前内存任务自动生成，不再提供独立的“计算与输出”页面。

正向计算采用串行组合流程：01 正向入口成功后自动调用 03 的特征提取模式；03 结果保存在本次 01 `output/features/run_xxx` 下，结果浏览器合并显示两部分输出。

轨迹生成是纯后处理流程：读取当前任务 `01-正向计算/` 下最近一次成功运行的 `trajectory_history.csv`，不再次调用 01；随后调用 `postprocess_trajectory.py` 生成 `trajectory_metrics.csv` 及轨迹图，也不调用 03 特征提取。若当前任务没有成功的正向结果，界面会提示先运行正向计算。

结果按任务文件归档到 `output/tasks/任务名_短编号/`。同一个任务执行不同模块时共用这个任务目录，其下直接显示 `01-正向计算/`、`02-智能预测/`、`轨迹生成/`、`03-相似度评估/`、`04-红外场景构建/`；每次执行的请求、日志、运行记录与后端结果保存在对应模块的短运行目录中。

智能预测不再提供“载入后端参考任务”。调用 02 或包含代理预测链的 04 前，软件自动将固定场景、运动、环境与观测参数调整为冻结代理模型的参考工况，同时保留当前统一内部热源、红外发射率和太阳吸收率，并自动令红外反射率等于 `1 - 红外发射率`。

相似度评估页面通过两个“选择文件夹”按钮分别选择参考和候选正向计算的 `output` 目录；选择时立即检查温度与红外历史文件。Evaluation config 不再由用户选择，运行时固定加载后端默认 `03-相似度评估/01-输入文件/similarity_config.json`。

软件启动时自动选择 `output/default.task.json`；文件不存在时会按界面默认参数创建。“任务设置”保留“打开任务”和“保存任务”，不再提供“新建任务”。打开任务会恢复任务信息、目标参数、各目标独立覆盖、运动、场景以及环境与观测参数。任务文件使用 `preprocess-task-v1` 版本标识，它是可再次编辑的工程文件，与运行时自动生成的 `request.json` 不同。任务文件的保存位置不参与计算路径解析：计算始终使用当前内存参数，运行输出仍统一进入 `output/tasks/`。
